--- EXECUTIVE SUMMARY ---
Co-developed with Yoav Shragay, this is a high-performance server-client classification
system implementing K-Nearest Neighbors from scratch in C++. The system handles multiple
concurrent clients over TCP sockets, allowing users to upload datasets, configure
algorithmic parameters, and retrieve classification results—all through an interactive CLI.

--- ARCHITECTURAL STRATEGY / TECHNICAL APPROACH ---

1. Command Pattern for Extensible Operations:
   - **Context:** Server needed to support 6+ distinct operations without becoming
     a monolithic switch statement nightmare.
   - **Solution:** Implemented Command pattern with abstract `command` base class;
     each operation (upload, classify, settings, results) has its own `execute()` method.
   - **Reasoning:** Open/Closed Principle compliance—new features require a new class,
     not modifying existing server loop.

2. Dependency Injection via Abstract I/O Layer:
   - **Context:** Core logic needed to work identically whether input came from
     console (CLI) or TCP socket.
   - **Solution:** Created `DefaultIO` abstract class; `SocketIO` and `StandardIO`
     implement `read()` and `write()` for network and console respectively.
   - **Reasoning:** Commands are transport-agnostic—they call `dio->read()` without
     knowing if they're talking to a socket or terminal. Enables instant switch
     between local testing and network deployment.

3. Strategy Pattern for Distance Metrics:
   - **Context:** KNN algorithm needed to support 5 different distance calculations.
   - **Solution:** Abstract `distanceAlgo` base class with virtual `checkDistance()`;
     each metric (AUC, MAN, CHB, CAN, MIN) is a subclass that overrides it.
   - **Reasoning:** Users switch metrics at runtime without modifying algorithm logic;
     clean polymorphic design.

4. Thread-Per-Connection Concurrency:
   - **Context:** Server needed to handle multiple simultaneous clients.
   - **Solution:** Each client connection spawns a detached thread with its own CLI
     instance. One client uploading a large CSV doesn't block others.
   - **Reasoning:** Simple, effective model for expected connection count; POSIX
     threads provide low-level control over concurrency.

--- ALGORITHMIC IMPLEMENTATION ---

The classifier supports 5 distance metrics, switchable at runtime:
- **AUC:** Euclidean Distance (standard geometry)
- **MAN:** Manhattan Distance (grid-based)
- **CHB:** Chebyshev Distance (maximum coordinate difference)
- **CAN:** Canberra Distance (weighted relative difference)
- **MIN:** Minkowski Distance (generalized p-norm metric)

--- KEY FEATURES ---
- Upload train/test CSV datasets over network for classification
- Configurable K value and 5 distance metrics at runtime
- Real-time classification results displayed or saved to file
- Multi-client support with concurrent session handling
- Robust input validation and error handling throughout
- Menu-driven CLI with clear user feedback

--- ENGINEERING PHILOSOPHY DEMONSTRATED ---
1. **Systems Programming:** Low-level TCP sockets, memory management, pointers,
   thread safety—working closer to the metal than typical web development.
2. **Design Patterns:** Heavy use of Command and Strategy patterns for maintainable,
   extensible architecture that follows SOLID principles.
3. **Separation of Concerns:** Abstract I/O layer decouples business logic from
   communication transport.
4. **Algorithm Implementation:** KNN classifier with 5 distance metrics implemented
   from scratch, not using ML libraries.
