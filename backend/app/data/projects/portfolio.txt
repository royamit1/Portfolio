--- EXECUTIVE SUMMARY ---
This project is the culmination of my journey into Full-Stack AI Engineering. It's a
custom-built Retrieval-Augmented Generation (RAG) system designed as my "Digital Twin."
Unlike static portfolios, it uses Hybrid Search (Vector + Keyword) to answer questions
about my career, with a "Transparent AI" interface that visualizes the thinking process
in real-time via Server-Sent Events.

--- ARCHITECTURAL STRATEGY / TECHNICAL APPROACH ---

1. Hybrid Search for Accurate Retrieval:
   - **Context:** Pure vector similarity sometimes missed exact matches (dates, names).
   - **Solution:** Implemented hybrid search combining pgvector semantic search with
     full-text keyword search using PostgreSQL's ts_vectors.
   - **Reasoning:** Semantic search captures meaning; keyword search catches specifics.
     Combined results provide both relevance and precision.

2. "One Brain" Architecture (Refactored from "Two Brains"):
   - **Context:** Initial design used a summarizer chain before the chat agent—created
     a "Game of Telephone" that stripped nuance and caused false "I don't know" responses.
   - **Solution:** Removed intermediate summarization; gave GPT-4-Turbo direct access
     to raw, unfiltered text chunks from the vector store.
   - **Reasoning:** Single-agent architecture preserves context fidelity; accuracy
     improved dramatically after refactoring.

3. Server-Sent Events for Transparent AI UX:
   - **Context:** Standard RAG had 3-5 second "frozen" delays while AI thought—felt broken.
   - **Solution:** Custom SSE protocol streaming structured JSON events (`tool_start`,
     `tool_end`, `token`) instead of just text.
   - **Reasoning:** Turns "waiting time" into "trust-building time"—users see the AI
     actively searching my resume via the animated "Glass Pill" component.

4. Cloud-Native Infrastructure (Docker → Serverless):
   - **Context:** Started with Docker Compose locally; needed production deployment.
   - **Solution:** Decoupled monolith → Render (backend), Vercel (frontend), Neon
     (serverless Postgres), Upstash (serverless Redis for chat history).
   - **Reasoning:** Serverless databases scale to zero (cost-efficient); managed
     CORS and environment variables across providers for secure communication.

--- TECH STACK BREAKDOWN ---

**Backend (Python):**
- **Framework:** FastAPI with async endpoints
- **AI Orchestration:** LangChain (LCEL chains)
- **Model:** OpenAI GPT-4-Turbo
- **Vector Search:** pgvector extension on Neon PostgreSQL
- **Caching:** Upstash Redis (serverless) for chat history
- **Deployment:** Docker container on Render

**Frontend (Next.js):**
- **Framework:** Next.js 14 (App Router)
- **Styling:** Tailwind CSS + Shadcn/UI components
- **Animations:** Framer Motion (typewriter, Glass Pill, tour popups)
- **State:** Custom React hooks handling SSE streams
- **Deployment:** Vercel with automatic Git deployments

**Infrastructure:**
- **Containerization:** Docker + Docker Compose (local dev)
- **Database:** Neon (serverless PostgreSQL with pgvector)
- **CI/CD:** Git-triggered deployments on Render and Vercel
